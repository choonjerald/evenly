What to build (MVP → v1.1 scope)
--------------------------------

Implement the **MVP** end‑to‑end and scaffold **v1.1** hooks so they’re easy to finish:

### MVP (ship this)
1.  **Auth & profiles**: Sign in via Clerk; use Clerk profile name & avatar in UI.
2.  **Groups**: Create groups with name and homeCurrency; invite members by **email**; accept invite flow. Roles: owner/admin/member/viewer (enforce read/write rules minimally).
3.  **Categories**: CRUD per group with name, color, emoji, sortOrder; use in expense forms and filters.
4.  **Expenses**: Add expense with: payer, amount, currency, **date**, category, memo; split type **equal / shares / percentage / manual**; multiple participants; optimistic UI + undo (soft delete).
5.  **Balances**: Realtime per group/person balances based on double‑entry math (credits to payer; debits to participants).
6.  **Settlement suggestions**: Compute suggested transfers (greedy/min‑cost style) to minimize edges; show friendly “Settle up” UI; allow recording a manual payment.
7.  **Activity feed & notifications (basic)**: Log expense create/edit/delete and payments; simple unread count per user; show recent activity on group page.
8.  **Receipts**: Upload image/PDF (Convex storage or signed URL route is fine); attach to expense; show thumbnail & download. (OCR is stretch; skip.)
9.  **Export**: CSV export for group or single member.
10.  **Charts (basic)**: Spend by category/person with Recharts (bar/pie); monthly trend line.
11.  **Accessibility & UX polish**: Keyboard navigation, toasts, empty states, loading skeletons.

Data model & server rules
-------------------------
Extend the Convex schema and queries/mutations to match:
*   **Entities**: users, groups, members, categories, expenses, splits, payments, receipts, activity, notifications, invites.
*   **Indexes**: members by group/user; expenses by group/date; splits by expense; payments by group/time; activity by group/time; notifications by user/unread; invites by group/email.
*   **Permissions**: Only members can read group data. Owner/admin can manage roles & categories; payer/creator/admin/owner can edit an expense; payments are append‑only (allow “void” to create reversing entry).

**Math rules (must implement)**
*   **Balances** (home currency): for each expense, credit payer total; debit each participant share. For payments, subtract from sender and add to receiver.
*   **Split methods**:
    *   equal: divide total; distribute remainder deterministically (index order).
    *   shares: weights wᵢ → each owes total * (wᵢ / Σw).
    *   percent: pᵢ sum to 1; each owes total * pᵢ.
    *   manual: provided minor units must sum to total; validate.
*   Deterministic rounding in integers; no floating point.
